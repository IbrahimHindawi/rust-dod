# 2.2 Columns

`ecs/src/2.components/2.2.columns/columns.rs`

1.4 kept components in typed Vecs: `positions: Vec<Vec2>`. A world that works
for any component can't, because it doesn't know the types. It knows, from the
registry, each component's size and alignment, and that's enough.

A **column** is one component's array, kept as bytes. Row `r` is the `size`
bytes starting at `r * size`. Everything a table does with its data is a byte
operation on columns: grow, copy one row over another, zero a new row. None of
it depends on the type. The type comes back only at the edge, where game code
reads a column as `&[T]`.

This is also the one place in the course that needs `unsafe`, and the chapter
is as much about how little of it there is as about columns. This chapter
builds the column and exercises it by hand. 2.3 puts columns in a table.

## Step 1: what a column is

```rust
struct Column {
    blocks: Vec<Block>,
    size: usize,
    id: u32,
    info: &'static Info,
}
```

Bytes, plus how many bytes make a row, plus which component it holds. No count:
every column of a table has the same number of rows, so the table keeps that
once (2.3).

The bytes live in a `Vec` of 16-byte blocks:

```rust
#[derive(Clone, Copy, Default)]
#[repr(C, align(16))]
struct Block([u8; 16]);
```

Why not a `Vec<u8>`? Alignment. A `Vec<u8>` only promises its bytes start at an
address divisible by 1, and an `f32` must start at a multiple of 4.
`align(16)` makes every block, and so the start of the storage, a multiple of
16, which is enough for any component (the column checks that when it's made).
Rows are packed from the start, so every row of every component lands on an
address its type can live at.

## Step 2: rows are byte ranges

```rust
    fn row(&self, row: usize) -> &[u8] {
        &self.bytes()[row * self.size..(row + 1) * self.size]
    }
```

That's the whole addressing scheme: row `r` is the bytes from `r * size` up to
the next row. Copying and zeroing rows are ordinary slice operations:

```rust
    fn copy_row(&mut self, to: usize, from: usize) {
        let size = self.size;
        self.bytes_mut().copy_within(from * size..(from + 1) * size, to * size);
    }

    fn zero_row(&mut self, row: usize) {
        let size = self.size;
        self.bytes_mut()[row * size..(row + 1) * size].fill(0);
    }
```

`copy_row` is swap-remove's copy from 1.4, for any component.

## Step 3: growing

```rust
    fn grow(&mut self, capacity: usize) {
        self.blocks.resize((capacity * self.size).div_ceil(16), Block::default());
    }
```

`resize` makes room for `capacity` rows, rounded up to whole blocks, with the
new bytes zeroed. When the Vec needs a bigger allocation, it copies the rows
into the new one and frees the old one. That's the difference from rin-dod's
arena, which left the old block in place until the arena was cleared. Doubling
the capacity each time keeps the copies to a few per table over a whole game.

Either way, **the data moves when a column grows**, so anything that pointed
into the old block is left behind. In rin that's a silent bug. In Rust, a
reference into a column borrows it, and `grow` needs `&mut self`, so the
compiler won't let the two overlap. 2.5 comes back to this.

## Step 4: the byte views, and the unsafe

Everything above works on `&[u8]` and `&mut [u8]`, the column's bytes. Getting
those from the blocks is one line, and it's `unsafe`:

```rust
    #[allow(unsafe_code)]
    fn bytes(&self) -> &[u8] {
        // SAFETY: a Block is 16 initialised bytes with no padding, so the Vec's
        // buffer is `len * 16` initialised bytes.
        unsafe { std::slice::from_raw_parts(self.blocks.as_ptr().cast::<u8>(), self.blocks.len() * 16) }
    }
```

`unsafe` doesn't turn off Rust's rules. It marks a place where *you* promise
something the compiler can't check, here that the memory really is that many
initialised bytes. The `// SAFETY:` comment says why the promise holds. The
whole file starts with `#![deny(unsafe_code)]`, so `unsafe` is an error
everywhere except in items that say `#[allow(unsafe_code)]` by name. You can
find every unsafe line with a search.

## Step 5: the typed view, and why it's sound

```rust
    #[allow(unsafe_code)]
    fn slice<T: Component>(&self, count: usize) -> &[T] {
        assert!(self.id == T::ID, "a {} column read as {}", self.info.name, T::INFO.name);
        let bytes = &self.bytes()[..count * size_of::<T>()];
        // SAFETY: T is the column's component, so the bytes are `count` T's;
        // the storage is aligned to 16 and T needs at most 16; T is Pod, so
        // any bytes are a valid T.
        unsafe { std::slice::from_raw_parts(bytes.as_ptr().cast::<T>(), count) }
    }
```

This is the untyped/typed split in one function. Below it, bytes. Above it, a
`&[T]` that game code indexes like any slice. The `assert` catches the one
mistake the byte level can't: reading a column as the wrong component.

Turning bytes into `T`s is only sound if *any* bytes are a valid `T`. Some
types have byte patterns that aren't valid values: a `bool` that's neither 0
nor 1, or a reference that's null. Components must be **plain old data**,
promised by an unsafe trait:

```rust
/// Plain old data: what lets a column hold a component as bytes, zero a row,
/// copy a row with a byte copy, and hand the bytes back as the type.
///
/// # Safety
///
/// The type is Copy, has no padding bytes, and every bit pattern is a valid
/// value of it. That is a promise the compiler cannot check by itself, so the
/// trait is unsafe; pod! makes the promise only after checking it at compile
/// time.
#[allow(unsafe_code)]
unsafe trait Pod: Copy + 'static {}
```

`f32`, `u32` and `i32` are plain data. A struct is, if all its fields are and it
has no padding (padding bytes are uninitialised, and reading them as bytes
isn't allowed). The `pod!` macro declares a struct and checks both, at compile
time:

```rust
        const _: () = {
            const fn field_is_pod<T: Pod>() {}
            $(field_is_pod::<$ty>();)*
            assert!(size_of::<$name>() == 0 $(+ size_of::<$ty>())*, "a component has padding");
        };
```

Calling `field_is_pod::<bool>()` doesn't compile, because `bool` isn't `Pod`.
And a struct whose size isn't the sum of its fields' sizes stops the build with
"a component has padding". `component!` now goes through `pod!`, so every
component is checked.

That's the whole unsafe surface of the ECS: four one-line views (`bytes`,
`bytes_mut`, `slice`, `slice_mut`), each with its reason, resting on one checked
promise. The program also runs clean under Miri, Rust's interpreter for
finding undefined behaviour (`python tools/check.py --miri`).

## Step 6: rows stay rows across columns

Writing goes through the typed view:

```rust
        positions.slice_mut::<Position>(count)[row] = Position { at: Vec2 { x: i as f32, y: 1.0 } };
        healths.slice_mut::<Health>(count)[row] = Health { points: 50.0 + 10.0 * i as f32, max: 100.0 };
```

The program keeps two columns side by side, positions and healths, and moves
them together:

```rust
    let last = count - 1;
    positions.copy_row(1, last);
    healths.copy_row(1, last);
```

Same operation, each column using its own row size. Row 1 is still one
entity's data across both columns. That's a table in all but name.

## Run it

```
a position column has 8-byte rows, a health column 8-byte rows
    grew to room for 2 rows
    grew to room for 4 rows
    grew to room for 8 rows
five rows, written through the typed view:
    row 0  position ( 0.00,  1.00)  health  50 / 100
    row 1  position ( 1.00,  1.00)  health  60 / 100
...
row 1's health as the column stores it, bytes: 00 00 70 42 00 00 c8 42
    that is 60.0 and 100.0 as little-endian f32s; the column never knew
swap-removed row 1: row 4 moved into it, in both columns
```

The byte line is the point of the chapter. `00 00 70 42` is `60.0` as an
`f32`, and the column stored it without knowing it was a float, or a health,
or anything at all.

## Rust notes

| rin | Rust |
|---|---|
| `^u8` and an arena block | `Vec<Block>`: the Vec allocates, grows and frees |
| `c*.data[row * c*.size]&` | `&bytes[row * size..(row + 1) * size]`: a range of a slice, bounds-checked |
| `memcpy`, `memset` | `copy_within`, `fill`: safe, checked slice methods |
| `cast(c*.data, ^T); raw[0..count]` | `std::slice::from_raw_parts`, inside `unsafe { }`, with a `// SAFETY:` reason |
| any type can be cast to bytes | only `Pod` types, checked by `pod!` at compile time |
| `#[repr(C)]` | the same: fields in declaration order, laid out as C would |
| `#![deny(unsafe_code)]` | no rin equivalent: `unsafe` is an error unless an item allows it |
