# 1.4 The entity index

`ecs/src/1.entities/1.4.entity_index/entity_index.rs`

Handles fixed identity. Two costs from 1.1 remain: every array is as long as
the most entities, and every system walks all of it, skipping holes. This
chapter **packs** the data: live entities in rows 0 to `len - 1`, no holes,
so a system is a straight loop over the rows. That's the stream lesson 1
measured as the fast case.

Packing has a consequence that the rest of the course is built around:
**an entity's data no longer sits at its number, and it moves.**

To keep this chapter about the index, every entity is the same kind of thing:
a particle with a position and a velocity. Part 2 brings back different kinds,
each packed in a table of its own.

## Step 1: two halves

```rust
#[derive(Clone, Copy)]
struct Slot {
    generation: NonZeroU32,
    row: u32,
}
```

```rust
#[derive(Default)]
struct World {
    slots: Vec<Slot>,
    free: Vec<u32>,

    entities: Vec<Entity>,
    positions: Vec<Vec2>,
    velocities: Vec<Vec2>,
}
```

The world now has two halves:

- **The slots**, indexed by the entity's number. A number never moves, so this
  is where a handle looks first. A slot holds the generation from 1.3, and now
  also **the row** the entity's data is in.
- **The rows**, packed. Each row's components side by side in the Vecs, and
  `entities[row]` saying which entity owns the row. All three Vecs always have
  the same length: the number of live entities.

The two point at each other: slot to row, row to entity. That two-way link is
called the **entity index**.

The fixed `[_; 8]` arrays are gone too. Part 1 used them to keep the first
chapters about one thing at a time; from here on everything is a `Vec`, and
the 8-entity limit goes with them.

## Step 2: spawning appends a row

```rust
        let slot = &mut self.slots[index as usize];
        slot.row = self.entities.len() as u32;
        let e = Entity { index, generation: slot.generation };
        self.entities.push(e);
        self.positions.push(p);
        self.velocities.push(v);
        e
```

The number comes from the free list or the end, exactly as in 1.3; the free
list is now a `Vec` used as a stack, so `pop` takes the last number freed. The
data goes in the next row, which is always the end of the packed rows. The slot
records where.

## Step 3: despawning swap-removes

To keep the rows packed, a hole can't be left behind. The last row moves into
it, called **swap-remove**, and `Vec` has it built in:

```rust
    fn despawn(&mut self, e: Entity) -> Result<(), Error> {
        if !self.alive(e) {
            return Err(Error::Dead);
        }
        let slot = &mut self.slots[e.index as usize];
        let row = slot.row as usize;
        slot.generation = slot.generation.checked_add(1).expect("a number has lived 4 billion lives");
        self.entities.swap_remove(row);
        self.positions.swap_remove(row);
        self.velocities.swap_remove(row);
        if let Some(moved) = self.entities.get(row) {
            self.slots[moved.index as usize].row = row as u32;
        }
        self.free.push(e.index);
        Ok(())
    }
```

`swap_remove(row)` moves the last element into `row` and shortens the Vec by
one. What no `Vec` can do for you is the part that matters:

```rust
        if let Some(moved) = self.entities.get(row) {
            self.slots[moved.index as usize].row = row as u32;
        }
```

The entity that owned the last row now lives somewhere else, and its slot must
say so. `entities[row]` is how we know *whose* slot to fix: without that
column, a moved row would be anonymous. If the despawned row *was* the last
one, nothing moved and `get(row)` is `None`. Forget these lines and the moved
entity's handle still finds a row, just the wrong one, and nothing crashes.

Swap-remove costs one row copy, however many rows there are. `Vec::remove`
shifts everything after the hole down to keep the order, at the cost of a copy
of every later row. ECSs don't promise order, so they take the cheap one.

## Step 4: reading through the index

```rust
    fn get_position(&self, e: Entity) -> Option<&Vec2> {
        if !self.alive(e) {
            return None;
        }
        Some(&self.positions[self.slots[e.index as usize].row as usize])
    }
```

Handle to slot to row. That's one extra lookup compared with 1.3, and it's
the price of packing. Systems don't pay it, because they don't go through
handles. In fact, the system no longer needs the world at all:

```rust
fn movement_system(positions: &mut [Vec2], velocities: &[Vec2], dt: f32) {
    for (p, v) in positions.iter_mut().zip(velocities) {
        p.x += v.x * dt;
        p.y += v.y * dt;
    }
}
```

No flags, no holes, no handles: every row is a live particle, so the system
takes the two columns as slices and streams them. `zip` walks them together and
stops at the shorter one, so the loop has no index to check. This is the loop
the rest of the course works to keep. Calling it hands it two fields of the
world at once:

```rust
    movement_system(&mut w.positions, &w.velocities, 0.5);
```

## Step 5: checking the invariant

Rows move all the time, and one missed slot update corrupts the world
silently. So the world can check itself:

```rust
    fn verify(&self) -> u32 {
        let mut problems = 0;
        for (row, &e) in self.entities.iter().enumerate() {
            if !self.alive(e) {
                println!("verify: row {row} holds dead entity {e}");
                problems += 1;
            } else if self.slots[e.index as usize].row as usize != row {
                println!("verify: {e} is in row {row}, its slot says row {}", self.slots[e.index as usize].row);
                problems += 1;
            }
        }
        let live = self.slots.len() - self.free.len();
        if live != self.entities.len() {
            println!("verify: {} rows, {live} live entities", self.entities.len());
            problems += 1;
        }
        problems
    }
```

**The invariant: every row belongs to a live entity whose slot points back
at that row, and there are as many rows as live entities.** Every structural
change in this course has to keep it true. When something goes wrong later,
run `verify` first.

## Run it

```
spawned 5 particles
    row 0  0:1  position ( 0.00,  0.00)
    row 1  1:1  position ( 1.00,  0.00)
    ...
    row 4  4:1  position ( 4.00,  0.00)
    slots:  0 -> row 0  1 -> row 1  2 -> row 2  3 -> row 3  4 -> row 4
despawn 1:1, in row 1: the last row moves into the hole
    row 0  0:1  position ( 0.00,  0.00)
    row 1  4:1  position ( 4.00,  0.00)
    row 2  2:1  position ( 2.00,  0.00)
    row 3  3:1  position ( 3.00,  0.00)
    slots:  0 -> row 0  1 free  2 -> row 2  3 -> row 3  4 -> row 1
despawn 4:1, which the last despawn moved: its handle still finds it
...
verify: 0 problems
```

Follow `4:1`: it starts in row 4, moves to row 1 when `1:1` is removed, and its
handle still finds it there because its slot was updated.

## Part 1 in one picture

```
handle 4:1 ──> slots[4] { generation 1, row 1 } ──> rows[1] { owner 4:1, position, velocity }
```

- **Handles** never change: they're what the rest of the game keeps.
- **Slots** never move: one per number, holding the generation and the row.
- **Rows** move all the time, and stay packed so systems can stream them.

Part 2 keeps exactly this, and generalizes the one kind of row into tables,
one per combination of components.

## Rust notes

| rin | Rust |
|---|---|
| `[8]kayan_slot` and a count | `Vec<Slot>`: grows as needed; `len()` is the count |
| a free list with `free_count` | `Vec<u32>` with `push` and `pop`, which returns `Option<u32>` |
| copy the last row over the hole by hand | `vec.swap_remove(row)` |
| `if (row != last) { moved = entities[last]; ... }` | `if let Some(moved) = entities.get(row)`: `get` returns `None` past the end instead of stopping |
| a loop over `row` indexing two arrays | `positions.iter_mut().zip(velocities)`: two slices walked together, no index |
| `noalias []vec2` | `&mut [Vec2]`: a `&mut` slice is always the only way to reach that memory |
| passing `w&` and reaching the arrays inside | `&mut w.positions, &w.velocities`: two fields of one struct, borrowed separately |

`let slot = &mut self.slots[...]` is a *mutable borrow*: a name for one
element you can change through. While it's alive, nothing else may touch
`self.slots`, and the compiler checks that. In `spawn` the borrow ends after
its last use, before the pushes, which is why the pushes are allowed.
