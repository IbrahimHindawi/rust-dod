# 1.3 Generations

`ecs/src/1.entities/1.3.generations/generations.rs`

1.2 ended with a turret aiming at its own bullet. The number it remembered was
reused, and nothing could tell the old entity from the new one. The fix is
small and used by nearly every ECS: count each number's lives.

## The idea

Give each number a **generation**. Entity 1 in its first life is `1:1`. When
it's despawned, number 1's generation goes up to 2, so the next entity to
reuse it is `1:2`. A reference carries both numbers:

```rust
#[derive(Clone, Copy, PartialEq, Eq)]
struct Entity {
    index: u32,
    generation: NonZeroU32,
}
```

A reference with a generation is called a **handle**. The turret's target is
the handle `1:1`. After the drone dies and the bullet becomes `1:2`, the target
still says `1:1`, and `1:1 != 1:2`. One comparison catches the bug.

Why `NonZeroU32`? Generations start at 1, so 0 is never a real generation.
`NonZeroU32` makes that a rule of the type, and Rust puts the forbidden 0 to
use: an `Option<Entity>` stores its `None` there. So "no entity" is `None`, and
it costs nothing. The program checks: an `Option<Entity>` is 8 bytes, the same
as an `Entity`.

## Step 1: the world keeps generations

```rust
#[derive(Default)]
struct World {
    count: u32,
    generations: [Option<NonZeroU32>; 8],
    free: [u32; 8],
    free_count: u32,
```

`generations[i]` is the life number `i` is in now, or the life it'll be in
next if `i` is free; `None` means the number was never handed out. 1.2's
`alive` array is gone, because the generations already say it:

```rust
    fn alive(&self, e: Entity) -> bool {
        e.index < self.count && self.generations[e.index as usize] == Some(e.generation)
    }
```

A handle is alive when its generation is the one its number is in *now*.

## Step 2: despawn bumps the generation

```rust
    fn despawn(&mut self, e: Entity) -> Result<(), Error> {
        if !self.alive(e) {
            return Err(Error::Dead);
        }
        let i = e.index as usize;
        self.has_position[i] = false;
        self.has_velocity[i] = false;
        self.has_health[i] = false;
        self.generations[i] = e.generation.checked_add(1);
        self.free[self.free_count as usize] = e.index;
        self.free_count += 1;
        Ok(())
    }
```

The generation goes up *at despawn*, not at the next spawn. So a free number
already holds a generation that no handle has been given yet, and no handle
can match it. That's why there's no separate `alive` flag: "free" and "every
existing handle is stale" are the same fact.

Despawning a dead handle now returns `Err(Error::Dead)` and changes nothing.
In 1.2, despawning twice put the same number on the free list twice, and two
later entities would have shared it.

## Step 3: a result you can't ignore

```rust
#[derive(Clone, Copy, PartialEq, Eq, Debug)]
enum Error {
    Dead,
}
```

`despawn` returns `Result<(), Error>`: `Ok(())`, or why nothing happened. A
`Result` is *must-use*: dropping one unread is a warning, and this course
builds with warnings as errors. Where the program knows a handle is alive, it
says so:

```rust
    w.despawn(drone_a).expect("the drone is alive");
```

`expect` unwraps an `Ok` and stops the program with the message on an `Err`.
That's stronger than ignoring the result: if the belief is ever wrong, you find
out on that line.

## Step 4: generations start at 1

```rust
            assert!(self.count < 8, "the world is full");
            self.generations[self.count as usize] = Some(ONE);
            self.count += 1;
            self.count - 1
```

A brand-new number starts at generation 1, `NonZeroU32::MIN`. So no handle can
ever have generation 0, and "no entity" is `None` rather than a special handle.

## Step 5: every access checks

```rust
    fn get_position(&self, e: Entity) -> Option<&Vec2> {
        if !self.alive(e) || !self.has_position[e.index as usize] {
            return None;
        }
        Some(&self.positions[e.index as usize])
    }
```

Reading through a handle checks it first. A dead handle gives `None` instead
of whatever data now sits at the number. The turret checks its target every
time it aims, and picks a new one when the old one is gone:

```rust
    let p = match w.get_position(*target) {
        Some(p) => p,
        None => {
            println!("the turret's target {target} is dead; it picks {fallback} instead");
            *target = fallback;
            w.get_position(*target).expect("the fallback is alive and has a position")
        }
    };
```

## Run it

```
the turret aims at 1:1, at (10.00, 0.00)
drone 1:1 is destroyed and despawned
the turret fires: the bullet is 1:2, the same number in its next life
    entity 0:1  position ( 0.00,  0.00)  velocity -                health 500
    entity 1:2  position ( 2.00,  2.00)  velocity ( 4.00,  4.00)  health -
    entity 2:1  position ( 0.25,  9.50)  velocity ( 0.50, -1.00)  health 100
the turret's target 1:1 is dead; it picks 2:1 instead
the turret aims at 2:1, at (0.25, 9.50)
despawning 1:1 again: dead
no entity is None, and an Option<Entity> is 8 bytes, the same as an Entity's 8
```

The same moment that ended 1.2, and this time the handle knows.

## Notes

- **Cost:** a handle is 8 bytes instead of 4, and checking one is one load
  and one compare. Cheap enough to do on every access.
- **Running out:** `checked_add(1)` gives `None` after a number's 4 billionth
  life, and reusing it then stops the program at the `expect` in `spawn`,
  rather than silently wrapping around to a generation an old handle might
  hold. Some ECSs use fewer bits for the generation, packing index and
  generation into one `u32` or `u64`. The idea is the same.
- **What it doesn't fix:** the arrays are still as long as the most entities,
  and systems still skip holes. That's next.

## Rust notes

| rin | Rust |
|---|---|
| `kayan_status: enum[must_use] = { ok, dead }` | `Result<(), Error>`: must-use is built in |
| `_ = kayan_despawn(...)` | `.expect("why it can't fail")`: checked, not ignored |
| `*vec2`, or `null` | `Option<&Vec2>`: `Some(reference)` or `None`, and the compiler makes you handle both |
| `if (p == null) { ... }` | `match` on the `Option`: one arm per case |
| `printfmt("{}:{}", e.index, e.generation)` | `impl fmt::Display for Entity`, then `{e}` anywhere |
| comparing two structs field by field | `#[derive(PartialEq, Eq)]`, then `==` |
| `{}` as "no entity" | `None`, which `NonZeroU32` makes free |
